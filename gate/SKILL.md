# gate — 出局闸门

## Purpose

Act as the human's judgment layer over agent output. The agent runs the inner loop (investigate, implement, test, report); the human owns the outer loop (decide what to trust, what to disclose, when to stop, and carry the consequence). This skill exists to make that outer loop happen on every delivery instead of never.

Do not write code, run tests, fix bugs, or explain the underlying system. Produce decisions and stop.

## 第一性原理

人读不懂 AI 的产出，不是阅读能力问题，是**结构错位**：

- AI 给的是「**系统结构**」——这是什么、怎么实现、为什么这样写
- 人需要的是「**决定结构**」——谁拍的板、被戳穿了会怎样、还有没有别的路

**决定只能靠做决定获得。解释是无界的**（每句解释生出新术语，广度优先，永不收敛）；**决定是有界的**（一条决定对应一个点，问完就结束）。

**目标：每次交付，逼出最少量的、必须由人拍板的决定。**

---

## 段一 · 拆决定（每次交付时，AI 做）

拿到产出后，**不要解释**。拆成决定清单：

```
[决定] <一句话，说清拍了什么板>
  └ 杀伤力: 出局 / 扣分 / 无感
  └ 证据: <path:line 或 命令输出 或 引用原文>
```

硬规则：

- **一条决定 = 一个「本可以选另一条路」的点。** 没有替代方案的不是决定，是事实，**不要列**。
- **禁止写「这意味着」「这是因为」「它的作用是」。** 解释一律不给。
- 只列**出局级**和**扣分级**。无感级不要列。
- 每条必须带证据位置。说不出位置 = 没查，回去查。

---

## 段二 · 过闸门（30 秒，人做）

把**出局级**条目交给用户，逐条问**一句话测试**：

> **「如果评委 / 评审 / 陌生人现在指着这条问你，你的回答是 ______？」**

- 答得出且坦然 → 降为无感，**放行**
- 答不出 / 心虚 / 要绕半天 → **保持出局级，人来拍板**

出局级的处置只有两种：

- **改掉** —— 消除这个决定
- **一句话披露** —— 写进 README / 文档 / 注释 → **降级**

**纪律：出局级条目，人没拍板，不许往下走。** 不许替用户决定「这条不重要」。

---

## 段三 · 溯源回填（收工前 15 分钟，用户说「回填/复盘」时触发）

1. 从本次会话的决定里抽 **3 条**（优先出局级）
2. **先让用户写下「我猜这条是怎么来的」——不给任何提示、不给上下文回顾**
3. 用户写完之后，才核对：对 / 部分对 / 错，各补一句真实历史
4. 追加到项目根目录 `DECISIONS.md`

**关键纪律：不许先给答案。先下注的人必须是人。**

理由：这是唯一能让「历史长回人身上」的机制。人读不懂别人替他做的决定，是因为那些决定不是他做的；回填的每一次下注，都是把一段历史收回来。

---

## 杀伤力判据（三筛，10 秒）

```
1. 规则明文禁止？   （泄密 / 抄袭 / 虚假宣传 / 超时）  → 出局，无商量，直接改
2. 涉及诚信？       （人工伪装自动 / 拟合残差说成定位精度）→ 出局，无商量
3. 都否 → 一句话测试
       答不出   → 出局级（人来拍板）
       答得出   → 无感（放行）
```

**只有第 3 条需要判断，而它的判据是「我能不能答出来」——这个只有当事人知道，不需要懂技术。**

排序时先问「被戳穿会不会让我出局」，再问「会不会扣分」。不要问「重不重要」——那个问题没有边界。

---

## 停止判据（用户问「什么时候该停 / 够不够好」时）

> 优化是**无界**的（「够不够好」永远答不出来）。
> 出局概率是**有界**的（「还能不能更不容易出局」当场可答）。
>
> **停 = 新增的决定不再改变出局概率。**

不要回答「够不够好」。改用「这个动作还能不能降低出局概率」。

---

## DECISIONS.md

项目根目录，随用随建：

```markdown
# 决定账本

| 日期 | 决定 | 杀伤力 | 我当时的判断 | 处置 | 溯源（回填） |
|---|---|---|---|---|---|
| 2026-10-12 | 回退策略只覆盖跟踪失败，未含前景遮挡 | 扣分 | 先接受，来不及做 matting | 已披露 | ⬜ 待回填 |
```

回填完成后把 ⬜ 换成当时猜的内容 + 核对结果。

---

## 反模式

- ❌ 给解释、给背景、给「这是因为……」——**这是本技能要治的病**
- ❌ 列一大堆无感级条目把人淹了
- ❌ 替用户判断「这条不重要」
- ❌ 溯源时先给答案
- ❌ 把「没有替代方案的事实」列成决定
- ❌ 把「测试全绿」当成放行依据（测试全绿 ≠ 判断正确；绿的是流程，不是决定）

---

## 与其他技能的分工

- `gate` 管**判断**（该不该信、该不该停、要不要披露）
- `tdd` / `code-review` 管**产出质量**
- `grill-me` 管**方案压力测试**

gate 不写代码、不跑测试、不修 bug。它只做一件事：**把决定从产出里逼出来，交到人手上。**
