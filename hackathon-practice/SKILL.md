# Hackathon Practice

## 目标

把比赛结果拆成五个前置门：规则有效、黄金路径可运行、评委能复述、主张有证据、产品符合评分。任何一门接近零，新增功能暂停。

## 模式

- `准备` 读取官方规则、评分、截止时间、时区、提交字段、Discord 或其他官方渠道，建立一页赛事简报。
- `参赛` 按时间比例推进，先验证最高风险，再做纵向切片，最后冻结功能并交付。
- `复盘` 从聊天、提交记录、Git、运行日志和录屏重建时间线，区分事实、假设和决定，形成下一次可观察的规则。

## 硬规则

⛔ 未完成赛事简报前，不开始大规模开发。

⛔ 总时长前 25% 未跑通真实输入到最终输出，必须缩小范围或换题。

⛔ 到 50% 后冻结新功能；到 80% 后只做提交、录屏、干净环境冒烟和回退演练。

⛔ AI 可以提出选题、实验和取舍，不能替用户拍下不可逆的选题、诚信披露、停止或提交决定。

⛔ 合成数据只能证明流程；外部 API 成功只能证明调用；二者都不能冒充用户证据。

## 断线与用量

每次长任务开始前写入 `HANDOFF.md`，包含目标、当前决定、已验证事实、下一步、阻塞点和恢复命令。Codex 断线时先保存状态，再开新对话；新对话读取交接文件，不重复盲跑。连续两次相同失败后转为人工或离线回退，并记录原因。

## 输出契约

根据用户选择写入以下文件，缺少目标文件时创建：

- `HACKATHON_BRIEF.md` 赛事和评分证据。
- `DECISIONS.md` 不可逆决定、替代方案、证据和处置。
- `SUBMISSION_CHECKLIST.md` 提交字段、链接、权限、视频时长、运行命令和备用包。
- `RETRO.md` 事实时间线、失败分类、可观察指标和下一次触发动作。

交付前运行自检，确认文件存在、链接可访问、录屏在规则时长内、黄金路径能从干净目录运行。判断层交给 `gate`，方案对照交给 `project-challenge-lab`，技术故障交给 `diagnose`，赛后沉淀交给 `postmortem-note`。这些是路由关系，不会把其他 skill 的 `SKILL.md` 包含进本 skill；使用前需确认对应 skill 已单独安装或可发现，`diagnose` 当前属于外部可选依赖。

## 不触发

普通功能开发、单个 bug 修复、没有比赛截止时间的长期产品建设、只想表达挫败感而不准备采取行动时，不加载本 skill。
